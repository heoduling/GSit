# GSit 3.6.0.4 · Shiroha / Folia 26.2

小范围性能优化，保留既有玩法。基于非官方兼容分支，不替代上游的通用版本。

> **HibiscusCommons / HMCCosmetics 用户必须完整重启替换。**
> 本次没有修复第三方插件的热重载事件绑定；不能把 GSit 加载成功当作整套时装联动通过。

## 改了什么

- 活塞涉及的方块没有座位/躺姿时，跳过空快照及汇总集合分配。
- 保留全部收集后再移动/停止、对象去重、方向、`GET_UP_BREAK` 和事件优先级。
- 新增三项回归测试；没有修改调度器、数据库、配置、权限或发包逻辑。
- 与已测试的 3.6.0.3 产物逐项比较，只有 `BlockEventHandler.class` 和 `plugin.yml` 内容不同。

代码：`core/src/main/java/dev/geco/gsit/event/BlockEventHandler.java` 的 `handleBlockPistonEvent`；测试：`core/src/test/java/dev/geco/gsit/event/BlockEventHandlerTest.java`。

## 测量结果及边界

2026-10-16，同一 JVM / 平台线程，用真实旧、新 handler 字节码处理 12 个无坐躺对象的方块代理。每组预热 100 万次，再测三轮，每轮 100 万次，取中位数。

| 指标 / 每百万次调用 | 3.6.0.3 | 3.6.0.4 | 减少 |
| --- | ---: | ---: | ---: |
| 线程分配量 | 2,344,000,000 B | 56,000,000 B | 97.61% |
| 墙钟耗时 | 329.1607 ms | 219.0423 ms | 33.45% |
| 线程 CPU 时间 | 312.5 ms | 218.75 ms | 30.00% |

公式为 `(旧值 - 新值) / 旧值 × 100%`。这是包含反射/代理成本的局部基准，受 JIT、顺序和计时粒度影响；不是整服 CPU、TPS、MSPT 或常驻堆收益，也不证明修复了内存泄漏。

真实协议发包对照：16 个客户端、8 人躺下、固定装备，每版三轮、每轮约 15 秒。装备包数量中位数均为 **42,360**，减少 **0%**。观察到的编码字节差异不归因为优化；没有更改发包代码。
